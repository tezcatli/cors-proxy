# Le labo

On y **définit** la chaîne de lecture, pour l'objet de l'app : une base de tests de jeux vidéo (quels jeux un épisode teste, sur quelle fiche IGDB). On la valide sur ton jugement avant de la porter dans l'app. Le labo ne fait pas partie de l'app : celle-ci ne l'importe jamais et il n'entre pas dans l'image de prod.

```bash
./pull-prod-data.sh                                     # les données de la prod en dev (sans les comptes)
docker compose -f docker-compose.dev.yml up lab         # http://localhost:5050
docker compose -f docker-compose.dev.yml run --rm lab python -m pytest tests
```

- **`reference.json`** : les épisodes de référence. 30 cas ciblés, un par mode d'échec connu ; et un tirage stratifié de 24 épisodes transcrits, à graine fixe (4 émissions × 3 tiers de leur historique × 2), qui rend l'ensemble représentatif.
- **`spec.json`** (versionné) : la spécification, **ce que chaque épisode de référence contient vraiment, ses tests**, indépendamment de toute chaîne, celle de l'app comprise (l'app suivra). Un test, c'est un jeu vidéo auquel les animateurs ont joué et qu'ils jugent dans l'épisode ; l'objectif est une base de tests. Pour chaque jeu : `test` (vrai, ou faux pour une news, une mention, un jeu de société…) et sa fiche IGDB (`igdb`, ou `absent` d'IGDB). On la remplit dans la page « Juger » sur les propositions d'une chaîne, en une seule frise : les chapitres, et sous chacun les tests proposés (un clic écoute ; « lire le test » ou « texte » déplie la transcription, reliée au lecteur), chacun juste, « pas un test », ou sur une autre fiche (« changer », « absent d'IGDB »), plus « + test manquant ici ». On ne juge que les exceptions : **« Valider l'épisode »** accepte le reste, sur les fiches proposées, et passe au suivant. Seul un épisode validé est mesuré ; si une chaîne y propose un test jamais jugé, il repasse « à revoir ».
- **`scope.py`** : ce qui compte comme test, par définition — au moins 5 minutes sur le jeu, sauf s'il est nommé dans le titre (en dessous, impossible de distinguer un test d'une mention avec assez de certitude). Un test plus court que tu as jugé « test » est « hors champ » : ni attendu, ni faux.
- **`measure.py`** (et la page `/mesure`) : le score d'une variante sur les épisodes validés — tests justes, faux, manquants, sur une mauvaise fiche, à juger — et le critère d'arrêt ; `--compare` montre ce qui change d'une variante à l'autre.
- **`judge.py`** : les lignes à juger (les tests de la variante et les jugements déjà faits, un même jeu malgré l'orthographe), rangées dans leur chapitre, et le statut de l'épisode (à juger, validé, à revoir) ; **`spec.py`** : la lecture et l'écriture de la spécification.
- **`variants/`** : les chaînes comparées — des hypothèses, libres de tout fonctionnement —, chacune avec `run(episode) -> {chapters, tests}`. `current` est la chaîne de l'app telle qu'elle est, une variante parmi d'autres. `un_jeu` : pour les émissions dont chaque épisode est consacré à un seul jeu (Fin du Game), le test est le jeu (ou la saga) du titre, sur tout l'épisode, et rien d'autre ; les autres émissions comme `current`. `sans_palmares` : en plus, une remise de prix (« Les Silences d'or »), un palmarès, un classement n'est pas un test — un jeu qui n'y figure que comme entrée (`ranking`) n'est pas proposé. `sans_bande_annonce` : en plus, les « Bande-annonce » de Silence on joue (une question, des anecdotes) ne contiennent aucun test. `cinq_minutes` : en plus, seulement ce qui est dans le champ (`scope.py`). `fiches_v2` : en plus, la fiche de chaque test par la variante de résolution (`fiches.py` : la date ne départage que des homonymes, pas de renvoi vers le jeu parent, la date de l'épisode toujours donnée), décidée par `python resolve.py --fiches`. « Juger » montre toujours les propositions de la meilleure variante (`fiches_v2`, `server.DEFAULT`) ; on compare les variantes dans `/mesure`.
- **`snapshot.py`** : la base de dev, ouverte en **lecture seule**. Ce que le labo produit lui-même (lectures, réponses IGDB) va dans son propre cache, `data/lab.db` (non versionné) : pour les modules de l'app, c'est une seule base, dont `llm_cache`, `resolutions` et `igdb_games` réunissent ce qu'a fait la prod et ce qu'a fait le labo. Ces modules sont utilisés comme bibliothèques et ne sont jamais modifiés.
- **`resolve.py`** : pose les questions IGDB restées sans réponse (jeux trouvés par les lectures du labo, ou « aucune fiche ne convient ») avec la résolution de l'app, dans le cache du labo ; `--fiches` décide les fiches de la variante de résolution. Relancer le serveur ensuite.
- **`read.py`** : fait lire par le prompt actuel les épisodes de référence qu'il n'a pas lus (`docker compose -f docker-compose.dev.yml run --rm lab python read.py`, avec `OPENROUTER_API_KEY`).

**Critère d'arrêt**, fixé avant d'itérer : **aucun test faux, aucune mauvaise fiche**, et **au moins 90 % des tests attendus** trouvés.
