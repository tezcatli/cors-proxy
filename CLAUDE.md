# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Silence on Joue** companion app — a PWA that parses the SOJ podcast RSS feed, groups episodes by video game title, and lets users browse/play them. Access is invite-only via JWT auth.

## Stack

| Layer | Tech |
|---|---|
| Backend | Flask (Python), SQLite, Gunicorn (prod) |
| Frontend | Vue 3 + Pinia + Vue Router, Vite, Tailwind + DaisyUI |
| Reverse proxy | Nginx — a shared edge (prod only), owned by the separate `tezcat-edge` repo |
| Delivery | GitHub Actions → images on GHCR → the host pulls; nothing is built in prod |
| Runtime | Docker Compose for all environments |

## Commands

### Development

```bash
# Start the full dev stack (Flask hot-reload + Vite dev server)
docker compose -f docker-compose.dev.yml up --build
# App: http://localhost:5173 (Vite)  API alone: http://localhost:5000
```

In dev, Vite serves the app and proxies `/auth` and `/games` to Flask (`vite.config.js`). Flask never serves pages, in any environment. Dev runs the real auth — there is no bypass — so sign in with an account (`invite.py --admin` for the first one).

### Production

Deployment is CI-only — there is no manual build step, and nothing is built on the host.
Push to `main` and `.github/workflows/ci.yml` runs tests → pushes images to GHCR → calls
the reusable deploy workflow in the separate **`tezcat-edge`** repo. See `SETUP.md`.

```bash
# Roll back to a previous commit's images (seconds, no rebuild)
ssh user@tezcat.fr "cd ~/opt/silence && sed -i 's/^IMAGE_TAG=.*/IMAGE_TAG=<old-sha>/' .env \
  && docker compose -f compose.yml up -d"
```

### Prod data in dev

```bash
./pull-prod-data.sh        # prod's produced tables → the dev DB (stops/starts the dev backend)
```

**Prod produces, dev consumes.** Transcripts, LLM answers and IGDB resolutions are made by prod's pipeline; what dev decides travels by git (`corrections.json`, prompts and their versions) — so data only ever flows prod → dev, and dev needs no keys to see what prod shows (what you review in dev *is* what prod serves; an LLM recomputing in dev would not be). `tools/prod_data.py` exports an **allowlist** of tables (`PRODUCED`) in the prod container, so users, invitations and reset tokens never leave prod, and a table added later stays home until listed. The tables are copied with prod's schema and the dev backend migrates them at its next start, exactly as a deploy would.

### The lab (dev only): defining the reading pipeline against your judgment

While the pipeline is being defined (which games an episode is about, at which level, on which IGDB entry, which chapters), **prod only serves** (`INGEST=false` in the server's `backend_secrets.env`) and the definition happens in dev, on a snapshot (`./pull-prod-data.sh`):

```bash
docker compose -f docker-compose.dev.yml run --rm backend python ingest.py --transcribe-all --jobs 4
```

transcribes what prod hasn't, oldest first, N at a time, with prod's own code (an episode already transcribed is skipped; DeepInfra failing stops the run). On an episode's page, an admin in dev gets a **Labo** panel (`backend/lab.py`, `GET /games/lab/episode`, `PUT /games/lab/judgments`, `LabPanel.vue`): every game the pipeline sees in the episode — attached, or only read — with its source (title, description, reading), the kind and minutes of its section, the IGDB entry, and four verdicts of what it *should* be: consacré, évoqué, absent, mauvaise-fiche. They are written to `backend/lab/judgments.json` — git-tracked, reviewed in a PR like `corrections.json`, writable only in dev (prod answers 404). Each judgment states the expected outcome, so it stays a reference case whatever the pipeline produces next. **Stop criterion**, agreed before iterating: no wrong « consacré » (neither an episode attached to a game it isn't about, nor a wrong IGDB entry), and ≥ 90 % of all judgments met.

## Architecture

### Request flow

```
Browser → edge-nginx (443, ludo.tezcat.fr) → /*        → silence-web (static SPA)
          shared with other apps           → /auth/*   → silence-backend:8000
                                           → /games/*  → silence-backend:8000
```

The edge is a **shared** reverse proxy owned by the `tezcat-edge` repo; it fronts every app
on the host, one subdomain each. This repo owns only `deploy/silence.conf`, the fragment
that the pipeline drops into the edge's `conf.d/` as `10-silence.conf`. Two consequences
worth knowing before editing it:

- **Upstreams must go through a variable** (`set $up …; proxy_pass http://$up;`) so Docker
  DNS resolves per request. With a literal name nginx resolves at startup and refuses to
  start when this app is down — taking every *other* app on the host with it.
- **Aliases must stay app-prefixed** (`silence-backend`, `silence-web`). Compose also
  publishes the bare service name on the shared network, so a second app with a `backend`
  service would make `backend` resolve round-robin across both.

In dev, Flask handles everything directly on port 5000 (no Nginx).

### Backend (`backend/`)

- **`app.py`** — Flask app factory. Registers the auth and games blueprints and an unauthenticated `GET /healthz` liveness probe. API only: the SPA is served by nginx in prod and Vite in dev. (The repo dir is still named `cors-proxy` for historical reasons — there is no longer a generic CORS-proxy endpoint.)
- **`auth.py`** — Blueprint at `/auth`: invite-token-based registration, login, password reset. All tokens (invite, reset, JWT) are random `secrets.token_urlsafe` strings stored in SQLite. `require_admin()` gates the admin routes here and in `games.py`; it re-reads `users.is_admin` from the DB on every call (the JWT's `admin` claim is cosmetic — it only decides whether the SPA shows the admin UI — so a demotion applies immediately instead of at token expiry).
  **Account administration** (backs the `/admin/users` console): `GET /auth/users`, `PATCH /auth/users/<id>` (`{is_admin}`), `DELETE /auth/users/<id>`, `GET /auth/invitations` (pending only, with each token + `invite_url` so the console can copy or revoke them), `DELETE /auth/invitations/<token>`. Two invariants are enforced in the same transaction as the write, because either failure locks everyone out of this very console with no in-app way back: **you may not delete or demote yourself** (409), and **the last admin may not disappear** (409). Sequentially the self-check always fires first (only the last admin can target the last admin); the in-transaction count is what stops two admins demoting each other at once.
  `POST /auth/invite` accepts **either** credential: the `X-Admin-Key` shared secret (for `invite.py`/CI, which have no session) or an admin session. A mail that fails to send is logged, not raised: the invitation is already stored, so the response is still 201, with `email_sent: false` (likewise `reset-request` still answers 204 — a 500 there would also reveal which addresses have an account). Its optional `is_admin` is stored on the invitation row and copied into the account by `register()` — that is the whole invite-time grant, and `invite.py --admin` is how the first admin is bootstrapped. Deleting a user revokes their live sessions for free: `_bearer_user_claims()` re-checks that the subject still exists.
- **`models.py`** — Dataclasses shared across the backend: `Chapter`, `GameMention`, `Episode`, `GameAppearance`, `PodcastGame`, and the IGDB cache's `Resolution` (which game an appearance is) + `IgdbGame` (that game's data), joined for readers as `IgdbEntry` (`.resolution`, `.game`, plus pass-through `igdb_slug`/`name`/`data`/`is_child`). No logic.
- **`rss.py`** — Pure RSS feed parsing (no I/O, no state). Public API: `parse_feed(xml_bytes) -> list[Episode]`, `extract_game_names(title)`, `extract_legacy_names(title)`.
- **`games.py`** — Blueprint at `/games`: routes only — request validation, the two memoised read payloads (catalog/feed JSON bodies + ETags keyed by `catalog_state.data_version`), and wiring. The work lives in five modules (below, under *In-memory state*): `catalog_state`, `feeds`, `resolver`, `serializers`, `review`. **No live push** (the SSE stream is gone): reads are read-only, and `POST /games/refresh` answers once the new games are resolved. Key endpoints: `GET /games` (slim catalog, `igdb` field contains only `{ metacritic, coverImageId }`), `GET /games/<slug>` (full igdb + episodes + `nameSlugs`, plus `displayName`/`igdbName` so the picker can pre-fill the current override and show the true resolution), `GET /games/episodes` (full feed), `GET /games/episode?slug=<episode-slug>` (single episode with IGDB-resolved chapter annotations), `POST /games/refresh` (re-fetch the feeds, then `resolver.quick_pass`: read new episodes of LLM-read shows and resolve never-cached appearances IGDB-only within `resolver.REFRESH_BUDGET_S`, then plan a sweep), `POST /games/<slug>/igdb-refresh`. Admin-only (`require_admin`): `GET /games/resolution-stats` (per-podcast figures — incl. the ingestion's `episodes`/`transcribed`/`read`/`ingestErrors` from `ingest.stats()`, and `transcription` totals: hours and cost — + **every** group as `games`, each with a `status` of resolved/suspect/unresolved — classified server-side, filtered client-side, so a correctly-resolved game stays reachable; ~860 KB, admin-only, uncached), `GET /games/igdb-search?q=` (picker), `PUT`/`DELETE /games/corrections` (writes corrections.json; 409 where it's read-only), `POST /games/podcasts/<podcast_id>/igdb-refresh` (purge + background re-sweep of one show).
  `PUT /games/corrections` takes `igdbId` and/or `displayName` (at least one). **A rename must not re-resolve**: `display_name` is applied at response time by `serializers.group_display_name`, so changing it only bumps `data_version` (`catalog_state.bump_version`) — purging would burn a round of IGDB + Metacritic + HLTB calls to arrive at the same entry. Only an `igdbId` change asks a new question (`_reresolve` answers it and prunes the old one).
- **`llm.py`** — An LLM via OpenRouter (`Config.LLM_MODEL`, default `openai/gpt-6-luna`), for what a search engine can't judge. Off when `OPENROUTER_API_KEY` is unset; every caller falls back to the non-LLM path, so an outage never blocks the catalog. `ask(task, version, system, payload)` caches each JSON answer in `llm_cache` by (task, prompt version, input) — one call per input, ever; bump a task's version when its prompt changes. While the catalog is rebuilt, `any_version` lets an older prompt's answer stand in until the new one is cached — otherwise a prompt change would drop every LLM-read episode, and the prune would take their IGDB resolutions with them. `reviewed_games` says which games an episode *critiques* (for `games_by_llm` shows) — the hosts played it and give a verdict; news, best-of lists, series retrospectives and games named for comparison are left out. Resolution uses two tasks, and **the model never states a fact about a game** — the games newest to a news show are newer than its training: `suggest_titles` reads the name (other titles worth searching: a French title's international one, an abbreviation expanded — never a verdict, `[]` is just nothing to add), then `pick_candidate` judges IGDB's candidates on their names, other names and release dates against the episode's date (an id outside the candidates is distrusted; « none fits » is the only negative verdict, and it is about the evidence). Answers are provisional: they are reviewed in the resolution console (in dev), and what it commits to corrections.json wins. `read_transcript` reads an episode's transcript (see `ingest.py`) into sections — title, the video game it is about (or null), and, for a video-game section, its `kind` (`KINDS`; what it is, not whether it counts — feeds.py decides) and the hosts' `opinion` — `verdict` None when nobody gives one, else one vote per host, **averaged on three steps** (`VERDICTS`: negative · mixed · positive — the model is asked for « enthusiastic » too, but two readings of 20 episodes disagreed on enthusiastic/positive 11 times out of 58, against 7 on every other boundary together, so it counts as positive), by `verdict()` (a tie goes to « mixed » — three positive voices and one negative are mixed; a vote written « Name: verdict » counts without the name — who spoke can't be told from a transcript), plus ≤ 3 pros/cons and the second the verdict is stated. Its cache input only *identifies* the transcript (guid + transcript model, with the title and description it is read with); the transcript itself is sent as `ask(message=…)`, so the cache doesn't hold a second copy. The episode's title and description are given as context and **their spelling of names wins** — speech-to-text writes « GICNEP » for Jiknep — and the language is named outright (told « the episode's language », the model answered in Spanish 2 times out of 3 on an English show).
- **`igdb.py`** — Internal IGDB helpers only. Looks up game metadata from IGDB API (Twitch OAuth) via a persistent `requests.Session`. Rate-limited to 4 req/s. `_resolve_canonical` resolves DLCs/versions to their parent game using inline nested fields in the query (no extra API call). `IgdbResult` includes an `is_child` flag set when the result was redirected to a parent. `fetch_time_to_beat(igdb_id)` is the IGDB `/game_time_to_beats` fallback for durée de vie. `fetch_by_name(name, window)` filters/prefers releases inside a `(lo, hi)` window (`window_around(ts)`: a year before a day to six months after); with no window it instead breaks name-score ties toward the **earliest** release (`_rank_results(prefer_earliest=)`), since IGDB lists ports and re-releases under the identical name. `search_games(q)` backs the admin picker and the LLM's candidates: raw IGDB matches with release year, `releaseDate` and `alternativeNames` (localised titles), no window, no canonical redirect, no ranking — a human or the LLM is choosing.
- **`metacritic.py`** — Scrapes the real critic Metascore from the public Metacritic game page (JSON-LD `ratingValue`). No API; best-effort + gently rate-limited (~1 req/1.4 s) with its own 3 s timeout (a stalled page used to hold the sweep for the full `REQUEST_TIMEOUT`), gated by `Config.METACRITIC_SCRAPE`. Any failure (404, Cloudflare block, parse error) returns `None` and the caller keeps IGDB's aggregate. `resolver._write_game()` overrides the cached `metacritic` with this when found.
- **`hltb.py`** — HowLongToBeat main-story completion time via the unofficial `howlongtobeatpy` lib. No official API, so every failure path returns `None`; rate-limited (~1 req/1.2 s). Primary source for `timeToBeatHours`, with `igdb.fetch_time_to_beat` as fallback. The lib is an optional dep — if it isn't installed the import is swallowed and HLTB is skipped (IGDB fallback used).
- **`corrections.json` + `corrections.py`** — **The single source of truth for name→IGDB corrections.** The JSON file holds the data (git-tracked: reviewed in a PR, survives a DB wipe, applies to every deployment); the module loads, validates, looks up and writes it. There is deliberately **no second store** — an earlier design had a `resolution_overrides` DB table alongside this, which duplicated the `igdb_id` pin and needed a precedence rule; the file won because a DB row is invisible to review and dies with the volume.
  - Entry = `podcast_name` + exactly one of `igdb_id` (pin, bypasses the search) or `search_name` (search this instead); optional `display_name` (applied at response time in `games.py`, so it composes with a pin), and optional **scopes** `hint_date` (episode published that UTC day) and `podcast_id`. An entry applies when every scope it declares matches; the most specific match wins (`_specificity`), so a bare entry is the name's fallback.
  - `load()` **fails loudly** on an incoherent entry (unknown field, `igdb_id`+`search_name` together — the search would be dead config — or two entries sharing a name *and* scope, where one could never apply). A test asserts the shipped file loads, so a bad commit fails CI rather than the prod container.
  - Entries are matched by `make_slug(podcast_name)`, so a spelling that doesn't match the feed's exact wording silently does nothing — `unmatched_slugs()` logs those at each feed re-parse, and `_key()` uses the slug too so write-identity matches read-identity.
  - `upsert(podcast_name, podcast_id='', *, igdb_id=None, display_name=_UNSET)` **merges** rather than replaces: pinning a game and renaming it are independent decisions, so neither may discard the other. Setting `igdb_id` drops any `search_name` (a pin bypasses the search, and `_validate` rejects the pair); `display_name=''` clears the override, omitting it leaves it alone.
  - **Writing is a dev-time activity.** `is_writable()` is True in dev (the repo is bind-mounted into the container) and False in prod (`COPY . .` bakes the file into a root-owned image layer and the app runs as `appuser`; a write would be permission-denied *and* discarded on the next build). The admin endpoints 409 when it's False. `_write()` is atomic (temp + `os.replace`) and **carries the original file's mode/owner across** — `mkstemp` makes a 0600 file owned by the writer, so without that the dev container (root) leaves `corrections.json` root:root 0600 and the human can't `git diff` or commit it.
- **`podcasts.py`** — The feed registry. Each `Podcast` carries its feed URL, the title→game-name extractor for that show's title convention, and `use_date_hint`: whether the episode's publication date is evidence of *the game's* release date. True for Silence on Joue (covers new releases); **False for Fin du Game**, a retrospective show where the date window would resolve a 1997 game to an unrelated 2026 release. Feed URLs are env-overridable (`<ID>_FEED_URL`). **Triple Click** and **The Besties** (English, review-focused; their titles don't reliably name the game — "Wolverine Is a Disaster") set `games_by_llm`: an LLM reads each episode's title and description and says which games it *critiques* (not every game discussed); an episode critiquing none is left out. Once an episode's transcript is read, its games are the ones the reading says it critiques instead — the description misses games (« Control Resonant Rewards Your Patience » also reviews *Gears of War: E-Day*). `language` (`fr`/`en`) is what the hosts speak, sent to Whisper and named to the reader. `skip_title` drops items that aren't the show (Maximum Fun's Beanscast teasers) before anything is asked. Without the LLM these shows contribute no episodes.
- **`db.py`** — SQLite at `backend/data/users.db`. WAL mode. Seven tables: `users` (incl. `is_admin`), `invitations`, `reset_tokens`, `resolutions`, `igdb_games`, `llm_cache` (see `llm.py`), `transcripts` (one row per episode guid the ingestion tried: the transcript once it succeeded — `segments` JSON `[[start, end, text]]`, NULL until then — its `model`, `duration`, `cost` as billed, and the backoff fields of the step that failed last; see `ingest.py`; not loaded into memory). The IGDB cache is **two tables because it holds two decisions with different keys and lifetimes**. `resolutions` is keyed by **question** (`questions.Question.key`), one row per question however many appearances ask it: `igdb_id` (NULL = no candidate fits, the question is open), `is_child` (1 if resolved to a parent game), `decided_at`, `method` (`pin` = a curator / `llm` / `search` = IGDB's ranking alone; NULL on legacy rows, accepted as is), `titles` and `candidates` (JSON: the LLM's reading and the candidate ids judged — what the answer was decided on), and the backoff fields. `igdb_games` is keyed by `igdb_id`, one row per game: `igdb_slug` (IGDB's own slug, used for URL routing), `name` (canonical IGDB name), `data` (JSON blob), `fetched_at` (the TTL runs from here), `enriched` (0 until Metacritic/HLTB have run). No foreign key: an answer may briefly point at a game being re-fetched. `init_db` migrates the legacy one-row-per-appearance `igdb_cache` (`_split_igdb_cache`): games straight into `igdb_games` (each keeping its enriched-then-newest copy), decisions into a transit table `appearance_resolutions` — a question needs the episode's show and date, so they become answers at the first complete catalog build (`catalog_state.adopt_appearance_resolutions`: a row answers its appearance's question when it was resolved under the correction now in force — what the legacy `correction_sig` recorded — and a question inherits only when its appearances agree; when they disagree it has no answer yet, so the LLM judges it like any other, each such question logged. Measured on a prod copy: 2 947 rows → 2 774 answers, 2 questions left for the LLM). Loaded into memory at startup.
- **`config.py`** — All config from env vars; `Config.DEBUG` only relaxes dev ergonomics (no insecure-`JWT_SECRET` refusal, full invite/reset links in the logs, warm-up in the reloader child) — never auth, `Config.METACRITIC_SCRAPE` gates the Metacritic scrape. `DEEPINFRA_API_KEY` (optional) turns transcription on, `TRANSCRIBE_MODEL` picks the Whisper model, and `INGEST` (default true; **false in `docker-compose.dev.yml`**) runs the background ingestion — dev consumes what prod produced and ingests a sample by hand.

### Frontend (`frontend/`)

- **`src/lib/games.js`** — Thin API client for the `/games/*` endpoints: `fetchCatalog()`, `fetchGameDetail(slug)`, `refreshCatalog()`, `refreshGameIgdb(slug)`, `fetchEpisodes()`, `fetchEpisodeDetail(episodeSlug)`. Admin-only: `fetchResolutionStats()`, `searchIgdb(q)`, `setCorrection()`/`deleteCorrection()`, `refreshPodcastIgdb(id)`. All use `igdb_slug` as the identifier. No XML parsing — all feed processing happens on the backend.
- **`src/lib/igdbCdn.js`** — One-liner helper that builds IGDB image CDN URLs (`igdbUrl(imageId, template)`).
- **`src/lib/audioEngine.js`** — **The playback state machine and the only owner of the `<audio>` element** (created lazily, injectable via `setMediaFactory` for tests; no Vue imports). It exists because the element lies: Android Chrome releases a paused track's buffered data — sometimes the whole resource — while the tab is backgrounded, and a later `play()` can then hang with **no `playing`, no `canplay` and no `error`, forever**. So the engine separates **`intent`** (`play`/`pause` — what the user asked for, never inferred) from **`status`** (`idle|loading|ready|playing|stalled|paused|failed`), and never tries to predict whether the element is healthy:
  - `play()` tries the cheap thing (a plain `play()`, synchronously so it keeps the caller's **user gesture** — deferring it to `loadedmetadata` is what used to lose it) and only reloads when the element is provably broken (`error`, no src, `NETWORK_NO_SOURCE`).
  - A **watchdog** (`[6s, 10s, 14s]` by attempt, armed whenever playback is wanted but not happening, cleared on `playing`) escalates: reload → reload → **`failed`**. `failed` is the whole point — a bounded, visible dead end the UI offers to retry, instead of a spinner that never stops.
  - A reload re-attaches with a media fragment (`url#t=<anchor>`) so it is **one ranged GET at the offset** rather than load-then-seek; `loadedmetadata` keeps the explicit seek as a fallback only.
  - **`anchor`** is the last *trusted* position and the only thing a reload seeks back to: `timeupdate` is ignored while seeking and while a pending seek is still reporting the load's reset-to-0, or a retry would restart the episode from the beginning.
  - `NotAllowedError` (autoplay refused) sets `paused` rather than reloading — no reload can supply a missing gesture, but the next tap can.
  - `visibilitychange` / `online` / `pageshow` (bfcache) recover an unhealthy element when playback was intended. Element events fired while no track is loaded are dropped (`whileLoaded`), so teardown noise can't resurrect state.
- **`src/lib/platformIcons.js`** — Maps the backend's `platforms[].family` key (playstation/xbox/nintendo/pc/apple/android) to a monochrome brand-glyph SVG path (simple-icons, CC0) via `platformIconPath(family)`; unknown family → `null` (DetailView falls back to the lucide `Gamepad2` icon).
- **`src/lib/auth.js`** — JWT stored in `localStorage` under key `soj-auth-token`. `apiFetch()` attaches `Authorization: Bearer` header to every request and throws on non-2xx. `isAdmin()` reads the token's `admin` claim to show/hide admin UI only — never a security boundary (the server re-checks the DB).
- **`src/pages/ResolutionStatsPage.vue`** — Admin console at `/admin/resolution` (lazy-loaded; router `meta.admin` + `isAdmin()` guard). **The app's only desktop-first, dense surface** — its job is scanning ~1660 rows and comparing two names, so filters sit inline as `.tab-group` segmented controls rather than behind popovers, and sorting lives on the column headers (`setSort`'s click-again-to-flip idiom). Each row is the confrontation the page exists to judge: podcast name → IGDB name, with the cover as the fastest wrong-match detector and a left accent bar for status (green/amber/red from the score palette). Reuses the catalogue's two perf measures — a module-level `Intl.Collator` and a 140 ms query debounce — plus `useInfiniteScroll` (pageSize 80, `resetKey`); that's incremental reveal, not virtualization, so a fully-scrolled unfiltered list is ~1660 live rows. Structure copies DetailView's **fixed shell + inner scroller**: `.back-pill` is `position: absolute`, so a page that scrolls its own root scrolls the pill away. Table CSS stays scoped — SFC scoped styles code-split with the lazy chunk, keeping admin CSS out of the bundle every reader downloads. Shows a banner while `pending > 0` (a half-swept cache reads exactly like a quality problem) and goes read-only when `writable` is false.
  **`review.is_suspect` is tuned for signal, not rigour**: a false positive buries the real misses, while a miss is still fixable from the game's own page — so it passes spacing (`Astrobot`/`Astro Bot`), numeral style (`Hades 2`/`Hades II`, via `_numerals`), subtitles, word order and plurals (word overlap ≥ `_SUSPECT_OVERLAP`), and a row already ruled on in corrections.json (`serializers.correction_for`, surfaced as `corrected`) is dropped from the queue. Tuning against the live catalogue took it from 68 mostly-noise rows to ~50 mostly-real ones. Known residual false positives: abbreviations (`GTA V` → `Grand Theft Auto V`) and French titles (`Le Vaillant Petit Page` → `The Plucky Squire`).
- **`src/pages/AdminUsersPage.vue`** — Admin console at `/admin/users` (lazy-loaded, `meta.admin`), reached from `AccountModal`. The counterpart to the resolution console and deliberately its opposite: tens of rows, every action consequential, two of them irreversible — so rows are roomy, destructive actions need a **second tap on the same row** (`confirming`, no `window.confirm`), and a rejected action shows **the server's own message on the row that caused it** (`rowError`) rather than a global banner restating the rule in our words. Self-actions are disabled here *and* refused server-side. Sending an invitation displays the resulting link with a copy button — SMTP is optional in this deployment, so without it that link is the only copy of the invitation. Toggling your own admin flag calls `auth.refresh()`, since the `admin` claim that decides what UI shows lives in the JWT. Styles stay scoped so they code-split with the lazy chunk.
- **`src/lib/admin.js`** — API client for the `/auth/*` account-admin endpoints. Separate from `lib/auth.js` (which every session loads) so it ships with the admin chunk; unlike `apiFetch`'s other callers it must set `Content-Type: application/json` explicitly, or Flask's `get_json()` sees nothing.
- **`src/components/IgdbPickerModal.vue`** — Two independent decisions, separated in the UI: « Nom affiché » (writes `display_name`; saving it alone costs no IGDB call) and the IGDB picker below it (writes `igdb_id`). Debounced search with stale responses dropped by sequence number. Offers a podcast scope selector only when the game spans both shows. Also reachable from `DetailView` (wrench icon), but only when the entry maps to exactly one podcast name. **A correction is keyed by one `podcast_name`**, so for an entry merging several spellings the picker warns that only that spelling moves; `_group_summary` reports such a group under its *resolving* (best-member) name and lists every `nameSlugs` behind it, rather than picking one by dict order.
- **`src/stores/games.js`** — Central Pinia store. Loads `all` games from the catalog, exposes `filtered(query)` with sort (alpha / date / metacritic) and a `selectedPodcast` filter (persisted to `soj-podcast-filter`). That podcast choice is shared with the Épisodes tab: `EpisodesFeed` filters on `ep.podcast?.id` and `AppHeader` shows the Podcast group of the popover on both tabs (sort + « résolus uniquement » stay catalog-only). No live updates: `load()`/`refresh()` are one request each, coalesced by an in-flight guard. New games appear through pull-to-refresh (whose response already carries them) or the next load.
- **`src/stores/player.js`** — Track metadata, listening-progress tracking, **and the only driver of `lib/audioEngine.js`**. It owns one engine and mirrors its state into refs (`status`, `currentTime` ← position, `audioDuration`, `volume`); `paused` / `buffering` / `failed` are **computed** from that (`paused` follows *intent*, so a tap flips the icon at once; `buffering` is the gap between intent and reality). Components never poke at flags — they issue commands: `play(track)`, `resume()`, `pauseAudio()`, `togglePlayback()`, `seek(t)`, `retry()`, `setVolume(v)`, `close()`. (The old `setPaused`/`setCurrentTime`/`setDuration`/`playVersion` element↔store plumbing is gone; `paused` used to be the command channel *and* the state, which is what let intent and reality drift apart.) Two `localStorage` keys: `soj-player` (the resumable snapshot `{ current, currentTime }`, restored *paused* by `App.vue` on load — `restore()` loads the engine with `autoplay: false` and sets a `restored` flag that drives the player's resume cue, cleared on `resume()`/`play()` or as soon as the engine reports `playing`) and `soj-progress` (`progressMap`: key `` `${episodeSlug}|${chapterTs}` `` → `{ currentTime, chapterEnd, gameSlug, ts, savedAt }`). Progress is written on a 5 s `currentTime` debounce, on chapter change, on `play()`, and on `close()`; `_pruneProgressMap` (180-day TTL by `savedAt` + newest-500 cap) runs on load and after each write to keep it bounded. Reads: `liveProgress` (computed, the currently-playing target), `getEpisodeProgress(slug, ts)`, `getGameProgress(slug)` (most-recently-saved entry), `getEpisodeLatestProgress(slug)` (newest-`savedAt` entry across all chapters of an episode), and `resumeTimeFor(slug, startTs)` (the central tap-resume rule: returns the saved `currentTime` when that chapter is partway through — `progressPct` between `PROGRESS_MIN_PCT` and `PROGRESS_DONE_PCT` — else `startTs`). **Single-worker note does not apply here — this is per-browser client state.**
- **`src/composables/useProgress.js`** — the one live-aware progress reader used by every consumer (`GameCard`, `EpisodeCard`, `EpisodeFeedCard`, `EpisodeView` chapter rows): `episodeProgress(episodeSlug, chapterTs)` and `gameProgress(gameSlug)` each return `{ pct, done }` (`done` at ≥ `PROGRESS_DONE_PCT`), checking the store's `liveProgress` first then the stored map. Views gate the bar on `pct > PROGRESS_MIN_PCT` and switch to the "listened" treatment when `done`. (Thresholds + `progressPct`/`formatTime` live in `lib/utils.js`.)
- **`src/composables/useEpisodePlayer.js`** — `playEp(ep)` builds the player payload and hands it to `playerStore.play()`. On tap it **resumes from saved progress** by setting `ts: playerStore.resumeTimeFor(ep.slug, ep.timestampSeconds || 0)` — the resume rule lives in the store so episode cards, `EpisodeView` chapter rows, and the "Reprendre" button all behave identically (partway → saved `currentTime`; untouched/finished → chapter start). (This is the *tap* resume — distinct from `App.vue`'s reload resume via `soj-player`, which restores paused with the cue.)
- **`src/components/AudioPlayer.vue`** — **presentational**: it renders player state and issues store commands, and holds no audio of its own (no `<audio>` tag, no media listeners — those live in the engine). The play button is a small state display: `Loader2` spinner while `buffering`, `Pause` while playing, `Play` when paused, and a red `RefreshCw` + the « Lecture interrompue — touchez pour réessayer » banner (`.player-error`) once `failed`. Mobile-only collapsed affordances: a tap-to-toggle grab handle (`toggleCollapsed()`, a non-button `<div>` so the bottom-sheet drag still works) and a bottom-edge progress hairline; both are hidden ≥900px where the inline seek bar shows position.
- **`src/composables/useMediaSession.js`** — Wires the browser MediaSession API (lock-screen / OS media controls) to the player store, feature-guarded so it's inert where unavailable. Every action handler goes through a **store command** (`resume`, `pauseAudio`, `seek`) rather than the element: the lock-screen play button is a resume like any other and must get the engine's recovery ladder. `buildMetadata()` keeps the OS card in sync with the **current chapter**: `title` is the chapter title whenever in a chapter (even one with no art), `artist` the episode name, plus a `chapterInformation` array. `currentArtwork()` mirrors `AudioPlayer`'s `playerCoverSrc` resolution — chapter cover → episode image in a chapter, launch-game cover → episode image otherwise. `syncMediaSessionMeta()` reassigns a **fresh** `MediaMetadata` for reliable cross-browser repaint, and watches on `currentChapter` / `episodeImageUrl` re-sync it. `previoustrack`/`nexttrack` seek between chapters (only registered when the episode has chapters).
- **`src/router.js`** — History-mode router at base `/`. The `beforeEach` guard forwards `?reset=` and `?invite=` query params to `/login`, redirects unauthenticated users to `/login`, and bounces non-admins off `meta.admin` routes to `/`.

### In-memory state and the backend modules behind `/games`

Core structures, all rebuilt from RSS + DB at startup. No per-request DB reads.
They live in **`catalog_state.py`**, as module attributes guarded by `catalog_state.lock`:

```
episodes        list[Episode]                  source of truth; owns all Episode objects
episode_index   dict[slug, Episode]            episode.slug AND url_slug → same Episode objects
game_index      dict[name_slug, PodcastGame]   one entry per unique game name
resolutions     dict[question_key, Resolution]  loaded from DB at startup
games           dict[igdb_id, IgdbGame]        loaded from DB at startup
data_version    int                            bumped on every change the read payloads derive from
```

**Always read them through the module** (`import catalog_state as state; state.game_index`),
never `from catalog_state import game_index`: `feeds.refresh_feed` *replaces* these objects,
so an imported name would keep pointing at the old catalog. The same rule makes tests patch
the module that owns a function (`patch('resolver.schedule_resolve')`), and makes it work —
`games.py` calls `resolver.schedule_resolve(...)`, not an imported copy.

Who does what:

- **`catalog_state.py`** — the structures above, plus the IGDB cache's write side: `store_resolution`, `store_game`, `load_igdb_cache_from_db`, `reconcile` (after each catalog build: adopt the legacy decisions once every feed is in, then prune), `prune_igdb_cache` (answers no appearance asks, then games no answer points at), `purge_cache` (forget answers so their questions are asked again; their games stay), `expire_games` (stale but still served, so a refresh doesn't drop appearances out of their group), `drop_game` (IGDB lost the id: the game and the answers pointing at it), `bump_version`. Readers take a joined snapshot with `entries()` (appearance → question → answer → game, by podcast_slug), `entry(game, episode)`, and `asked()` (every question the catalog asks).
- **`questions.py`** — **what resolving a mention asks.** `question_for(game, episode)` is the only place that combines an appearance, its show and corrections.json. Its **key** is a pure value — `name` (no correction: name · show · year, undated for a retrospective show; answered by the LLM), `search` (a curator's `search_name`/`hint_date`: the query, answered by IGDB's ranking) or `pin` (a curator's `igdb_id`: the answer) — but its **evidence is dated**: `aired` (the episode's date, or the curated day) and `window = window_around(aired)`, because a show covering new releases reviews a game out shortly before the episode and IGDB is full of older namesakes. `catalog_state.asked()` keeps each question as of its **first airing**, the episode nearest the game's release.
- **`feeds.py`** — RSS → catalog: conditional per-feed fetch, AI chapter injection, `build_indexes`, `refresh_feed` (skips the rebuild when every feed answered 304), `rebuild()` (recombine the feeds already fetched). LLM-read shows: `_apply_llm_games` uses **only cached** answers while rebuilding (which must not wait on a model); `unread_episodes()` / `read_episode()` are what `resolver.schedule_llm_reads` queues one worker job per episode from, and `read_new_episodes(deadline)` reads them in a row and rebuilds — `POST /refresh`'s quick pass, within its budget. Reads are sequential (one worker), so a first launch or a prompt-version bump re-reads every episode in ~1–2 h (~860 episodes, ~$0.40); `any_version` keeps the catalog whole meanwhile. **Transcript readings** are applied the same way, cached only: `_readings` looks up each transcribed episode's, `_apply_llm_games` takes an LLM-read show's games from it, and `_apply_readings` gives an episode **without chapters of its own** (description, then chapters.json — they win) the reading's sections as chapters, ads left out (`Episode.chapters_read`, replaced by the next reading); **keeps a game the title (or the description's reading) proposed only when the reading finds a section of it**, of whatever kind (`Episode.proposed` holds what was proposed, `games` is rebuilt from it on every pass — the title proposes, the reading confirms: a special's title isn't a game, « Le 500e épisode en public », « et la GDC »; on the 20-episode sample it dropped that one and kept the 13 real games); adds, for **every** show, the games it **critiques** that its title doesn't name, starting at their section (`GameMention.read`, replaced by the next reading — S17E16's title names two games, its hour on Microïds' catalogue five more). **The reader describes, the code decides**: each game section comes with its `kind` (`llm.KINDS`: review · impressions · ranking · news · recommendation · mention) and the hosts' opinion, and `CRITIQUE_KINDS` — the catalog's own criterion, the games the hosts played and judge, concluding or not, a best-of's entries included — is what is listed. A policy in the prompt could only change by re-reading every transcript (and drifted with each borderline case: a duration threshold let a five-minute trailer in); in code it changes in one line, over every reading already made; and gives each game mention the opinion of its section (`GameMention.critique`, matched by name like a chapter). `all_episodes()` is every fetched episode of the shows, the ones the catalog leaves out included — what the ingestion works through.
- **`transcribe.py`** — Whisper on DeepInfra (`Config.TRANSCRIBE_MODEL`, turbo: 0,0002 $/min) and the `transcripts` table. Off without `DEEPINFRA_API_KEY`. DeepInfra takes a file, not a URL (its JSON `audio` field is base64), so the audio goes through the server — **streamed** both ways: downloaded in chunks to a temp file and uploaded from it by `_Multipart`, a readable body with a length that `requests` sends as is (a 3-hour episode is 180 MB; prod has ~2 GB to spare, shared with other apps). Own `requests.Session` (also keeps tests' DeepInfra and OpenRouter mocks apart). **No Whisper `initial_prompt`**: with a lexicon DeepInfra dropped 60 % of an episode's words; names are fixed when the transcript is read. **Not sped up**, deliberately: DeepInfra bills the duration sent, and at ×1.5 (ffmpeg `atempo`, mono 64 kbit/s) S17E16 kept 99 % of its words and read identically for a third less — but that is ~6 $ once and ~1.5 $ a year, against ffmpeg in the image and a CPU minute per episode on a shared 2-vCPU host. At ×2 it lost 10 % of the words. Worth it only if the volume changes by an order of magnitude. `reading_input(episode, model)` is what identifies a reading in `llm_cache`.
- **`ingest.py`** — **Every episode transcribed once and read by the current prompt, newest first, one at a time, in one background thread** (`ingest`) — slow on purpose: the backlog (~2 300 h, ~28 $) is a one-off that takes a day or two, then a handful of episodes a week, on a small shared server. Off the worker because an episode takes a minute or more; what it writes is memos (`transcripts`, `llm_cache`), and the catalog changes only when the worker rebuilds it (`on_read` → a keyed `_rebuild_and_sweep`). `pending()` is the one definition of what is left (`_status`: transcribe / read / done; a failing episode waits out `utils.backoff`, its transcript kept); `stats()` counts the same for the console. A prompt-version bump re-reads every transcript without transcribing again. **DeepInfra failing** (`transcribe.Unavailable`: out of credit, a key refused, an outage — the upload failed, not the download) is not the episode's fault: it **pauses the whole ingestion** (`_step`; the tick's interval, doubling, up to a day) instead of failing each episode in turn — each attempt downloads the whole audio first, so a dry account would otherwise pull the backlog's ~100 GB for nothing, daily. The pause is in memory: after topping up, it lifts within a day, or at once with a restart of the backend. OpenRouter failing needs no such thing — a reading or a resolution that fails is cheap, and waits out its own delay. `resolver` starts it and the tick `wake()`s it. `python ingest.py <guid or url_slug>...` ingests named episodes at once — a sample in dev, where the thread is off.
- **`resolver.py`** — answering questions (`resolve`: read → gather evidence → judge → store; `refresh_game`), what counts as pending (`resolution_pending` — of an answer, `game_pending`, `appearance_pending`, `count_pending`), the failure backoff, the sweep (`schedule_resolve` → `_plan_sweep`, one job per question and per game), `quick_pass`, the tick, and startup (`startup_warmup`).
- **`worker.py`** — **The one thread that writes the catalog.** Every write — feed fetch, LLM read, resolution, game refresh, purge — is a job on it, so writers need no locks of their own: two resolutions of one appearance can't interleave and a sweep can't race a rebuild. Requests read under `catalog_state.lock`, or `worker.call()` a HIGH job and wait (`CALL_TIMEOUT_S`). Jobs are small — one appearance, one game, one episode — so a request waits behind the job running, never behind a whole sweep; a keyed job is queued once (resubmitting returns its Future, or moves it up). A job on the worker that `call`s it runs inline rather than deadlock. The one thing that runs beside it is the ingestion (`ingest.py`): its minutes-long episodes only fill memo tables, and hand the catalog change back to the worker as a rebuild. Tests set `worker.inline = True` (conftest), so jobs run in the test's thread.
- **`serializers.py`** — grouping appearances into catalog entries and turning them into payloads (`build_catalog`, `load_game`, `serialise_episode`…).
- **`review.py`** — the admin console's quality view: `is_suspect` and `resolution_stats`.

Corrections are **not** in this list: they live in `corrections.json` and are owned by
`corrections.py` (loaded at import, reloaded after each admin write).

**Catalog grouping is per *appearance*, not per name.** `serializers.group_members()` buckets every
`GameAppearance` by `_group_key` — the `igdb_slug` its question was answered with, falling back to its game's
`name_slug` while unresolved — and returns the cache snapshot the keys came from (rank within
a group against *that* snapshot, or a concurrent resolution can move an entry between reads).
`build_catalog`, `match_appearances` and `load_game` all work on those groups, so one
podcast name whose episodes resolve to different IGDB games splits into separate catalog
entries (Fin du Game on *Silent Hill 2* 2001 vs Silence on Joue on the 2024 remake) instead of
one silently absorbing the other's episodes — they ask different questions (other show, other
year). Conversely, name variants converging on one
`igdb_slug` still merge. `best_member` picks a group's representative (non-child first, then
newest `decided_at`). A name_slug that is *also* a real igdb_slug serves the resolved group;
the all-appearances fallback exists only so a stale `/game/<name_slug>` link still renders.

`resolutions` is written whenever `resolver.resolve()` answers and `games` whenever a game is fetched (on the worker); both are pruned to what the current appearances ask on each feed re-parse, so they stay bounded. All other structures are read-only from the perspective of HTTP handlers.

**Derived response caches.** `data_version` is bumped under `catalog_state.lock` on every feed re-parse that changed something (an all-304 poll keeps it), IGDB resolution, and `igdb-refresh` delete. `games._catalog_cache`/`_feed_cache` hold the *serialised* JSON body + ETag keyed by it, so repeat reads and 304 revalidations skip re-serialising/re-hashing.

**IGDB resolution — the LLM reads, IGDB knows.** An appearance doesn't get its own answer: it asks a **question** (`questions.py`), and every appearance asking the same one shares its answer. `resolver.resolve(question)` takes the same steps for every open (`name`) question:

1. **read** — `llm.suggest_titles`: other titles worth searching. Stored with the answer, so a question is read once; the LLM's context carries the first airing's date. Skipped for a `games_by_llm` show, whose names the LLM already gave.
2. **gather evidence** — `gather_evidence`: IGDB's `search_games` on the name and on each title read, plus `fetch_by_name` in the window around its first airing, which is always a candidate too — each candidate offered with its full release date, the evidence against older namesakes: IGDB's free-text search finds nothing for some games (« The Séance of Blake Manor ») and only DLCs and seasons for others (« Honkai: Star Rail », « Fall Guys »).
3. **judge** — a curator first (a `pin` question is fetched with `canonical=False`, so a curator's choice is never redirected to a parent game; a `search` question takes IGDB's ranking, the LLM staying out of a search a human chose), then `llm.pick_candidate` among the candidates, then IGDB's ranking alone (`method='search'`) while the LLM is unavailable or on `POST /refresh`'s quick pass (`use_llm=False`) — provisional: it stays pending while the LLM is on, so the sweep hands it over.
4. **store** — the answer under the question's key with its reading and candidate ids; the game it lands on once (`_store_game`), enriched with real Metacritic (`metacritic.fetch_metascore`) and durée de vie (`hltb.fetch_time_to_beat` → IGDB fallback) unless a fresh enriched copy is cached — so the scrapers run **once per IGDB game**. `enrich=False` (the quick pass) skips them — ~1–10 s per game against ~0.3 s for IGDB — and caches a new game as `enriched=0`, pending until the sweep completes it.

Judging names and release years needs no memory of the game, so **a game newer than the model's cutoff resolves like any other**: a wrong reading (« Silent Hill f » read as « Silent Hill ») only adds candidates, and the right one is in the window. Measured before this design on 20 doubtful names, the LLM fixed 8 of 12 bad matches (*Catetris* → *Tetris*, a French *Seigneur des Anneaux* title) and found *Professeur Layton et l'étrange village*.

**When is a question asked again?** Only when it has no answer (`resolution_pending`): never answered; failed and its backoff passed; answered by the ranking alone while the LLM is on; or **open** (no candidate fitted) past `IGDB_TTL_HOURS`, since IGDB adds games — and then the LLM is called only if the candidates changed (same evidence, same verdict). An answered question is never re-asked: not by a new episode, a new prompt version or model, nor its age — the TTL expires the *game's data*, re-fetched by id (`refresh_game`, `canonical=False`; `is_child` lives on the answer), because a fresh search can land on a same-name game IGDB added since and silently undo a right answer. Asking again takes a purge (an explicit igdb-refresh, which also expires the games involved — the one way to re-scrape before the TTL); an id IGDB no longer has drops the answers pointing at it. **A failure backs off**: an IGDB error, or the LLM unavailable when wanted, stores `attempts`/`last_error`/`retry_at` on the answer (keeping any previous one, which goes on being served) — the tick's interval, doubling, capped at a day; success clears them, and the console counts those appearances as `retrying` (« en erreur »), apart from open questions.

The background tick (`_periodic` queues a `_tick` job every `RESOLVE_RETRY_MINUTES`) polls the feeds — conditional GETs, nearly always 304 — queues unread episodes for the LLM, and plans a sweep over what **`appearance_pending()`** finds; the admin console's `pending` uses the same notion. That tick is what keeps the catalog fresh: `GET /games` never fetches, except on a cold start with nothing loaded.

**Applying a shipped correction to a running instance.** A correction changes the *question* its appearances ask (`pin|<id>`, `search|<query>|<scope>`, or back to `name|…` when removed), and `display_name` changes none, since a rename is applied at response time. Because `corrections.json` is baked into the image but the IGDB cache lives in a volume that survives deploys, that is all a curated fix needs: at startup the new question has no answer, the sweep answers *exactly* it, and the old one — asked by no appearance any more — is pruned. No fingerprint to compare.

**Single-worker constraint:** because this state lives in process memory (and the catalog worker — `worker.py`, the only writer — and the rate limiter are likewise in-process), prod must run gunicorn with `--workers 1` (see `backend/Dockerfile.prod`). Scaling to multiple workers silently breaks the cache, the resolver, and rate limiting — move that state to shared storage (e.g. redis) first.

### Slug model

Slug types that coexist:

- **episode.slug** — the RSS `<guid>` (fallback: `make_slug(audio_url)`, then `make_slug(title)`). Stable internal episode identity and a key in `_episode_index`. Also embedded in `podcast_slug` and used as the player's progress-tracking key. **Not** used in URLs (guids are often raw URLs).
- **url_slug** — `make_slug(episode.title)`, de-duplicated with a numeric suffix on collision. Human-readable; the **only** slug used for episode routing (`/episode/:slug`). Also registered as a key in `_episode_index`, so `GET /games/episode?slug=` accepts either the url_slug or the guid (legacy/cached links). Serialised as `urlSlug`.
- **name_slug** — `make_slug(game_name)`. Key in `_game_index`. One `PodcastGame` per unique game name.
- **podcast_slug** — `make_slug(game_name) + '-' + episode.slug` (the guid). An appearance's identity (`GameAppearance.podcast_slug`, the key of `catalog_state.entries()`); **not** a cache key — an appearance's answer is stored under its question.
- **question key** — `questions.Question.key`: `name|<podcast_id>|<year or undated>|<name_slug>`, `search|<slug(query)>|<scope>` or `pin|<igdb_id>`. Primary key of `resolutions`.
- **igdb_slug** — IGDB's own URL slug (e.g. `indiana-jones-and-the-great-circle`). Stored in `IgdbGame.igdb_slug`. Used for URL routing (`/games/<igdb_slug>`).

`make_slug` normalizes any run of non-alphanumeric chars to a single dash. IGDB slugs can contain `--` (e.g. `resident-evil-2--1`) which `make_slug` would destroy, so igdb_slug lookups always use the raw IGDB value, not `make_slug(slug)`.

### Shared contract

`contracts/api.json` declares expected HTTP status codes and response fields for every endpoint. Both the Python tests (`tests/contract.py`) and the JS integration tests (`tests/contract.js`) validate against this file — keep it in sync when adding or changing endpoints.

### Service worker

`frontend/sw.js` is registered by `main.js` at `/sw.js` with scope `/`. Cache invalidation on deploy is handled by the build-hash keyed cache name (the Vite `stampServiceWorker` plugin in `vite.config.js` replaces `__CACHE_VERSION__` with a hash of output bundles). The SW uses `skipWaiting()` + `clients.claim()` so the new version takes over immediately; `main.js` listens for `controllerchange` and reloads open tabs.

### Secrets

`backend_secrets.env` is git-ignored. Required keys: `JWT_SECRET`, `ADMIN_KEY`, `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET`, `RESET_BASE_URL`. SMTP keys are optional (links are logged to stdout when omitted), and so are `OPENROUTER_API_KEY` (no LLM without it) and `DEEPINFRA_API_KEY` (no transcription without it). See `SETUP.md` for the full reference.
